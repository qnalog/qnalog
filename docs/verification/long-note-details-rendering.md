# 长笔记折叠区测量

日期：2026-10-12。环境：Obsidian 1.14.4，Fresh 库，实时预览。下面的实测数据由维护者提供；本轮未从 Obsidian CDP 端点重新采样。

## 已有测量

每步向下滚动 500 px，并在两次 `requestAnimationFrame` 后读取视口内的 `.cm-line` 与 `details`。窗口必须保持前台，否则渲染暂停，读数会是 0。

| 变体 | 露出原始机器文本的步数 / 总步数 | `<details>` 首次渲染 |
|---|---:|---|
| 当前旧格式，6 段，数据行合计约 73 kB | 57 / 94 | 滚到末尾 |
| 去掉块内空行 | 57 / 94 | 滚到末尾 |
| 再去掉 `###` 段落标题 | 57 / 94 | 滚到末尾 |
| 数据折为每行 120 字符 | 未渲染 | 滚到底仍未渲染 |
| 数据约 36 kB | — | 未渲染 |
| 数据约 18 kB | — | 滚到末尾 |
| 数据约 7 kB | — | 滚动约 60% |
| 数据移到 `<details>` 外的单行隐藏元素 | 1 / 9 | 立即折叠 |
| 3 段短笔记对照 | 0 / 7 | 立即折叠 |

测量结果显示，渲染延迟随 `<details>` 总字符量变化。空行、标题和数据行换行没有改变延迟。转写完整记录因此放在折叠块之后的隐藏行内元素中；折叠块只保留标记、标题和可读转写文本。

## 本轮新增的测量脚本

运行 `node scripts/measure-note-details-rendering.mjs --vault=/path/to/Fresh --cdp=ws://127.0.0.1:PORT/devtools/page/ID`。脚本通过插件当前 `buildTextImportSourceDetails` 写入器生成 6 段长笔记和 3 段短笔记，随后生成旧格式对照。每篇样本还含有当前写入器生成的「录音中实时大纲（草稿）」折叠块；脚本输出该块来源覆盖记录的字符数，用于对照 5 kB 阈值。脚本用 Obsidian URI 冷开每篇笔记，通过 CDP 每步发送 500 px 鼠标滚轮事件，并输出每步的 details 数、open 数、可见机器注释行数、可见 `### 段落` 行数和 `scrollHeight`。结束时删除临时笔记。

本机 `obsidian help` 返回“CLI is unable to find Obsidian”，当前窗口没有可用的 CDP 地址。本轮未运行该脚本，因此没有把维护者先前的测量结果标作脚本复测结果。脚本运行时需要 Obsidian 保持前台；维护者仍需执行一次脚本复测并检查其输出。
